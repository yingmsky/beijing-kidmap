# beijing-kidmap

北京遛娃地图。**回答一个问题：现在这个点，带孩子去哪儿最合适。**

不是 POI 检索，是把「天气 + 太阳位置 + 树荫 + 人流 + 孩子年龄」算成一个分数，随时间实时变化。
单文件 HTML，双击即跑，不依赖任何 CDN 或构建工具。

---

## 它解决什么

家长的真实决策不是「附近有什么公园」，而是：

- 35°C 正午 → 该躲进博物馆，还是找片树荫？
- 傍晚 19:00 → 哪儿凉快又不晒？
- 3 岁和 10 岁，同一个地方的分不一样。

所以地图给出的是**排序**，不是列表。拖动底部时间轴，能看到整张图的点位颜色随时间推移整体翻转——
正午市中心一片浅（户外全军覆没），19:00 沿河和树多的地方翻深。

## 三个核心算法

**1. 太阳位置（本地算，可离线）**
NOAA 简化算法写死在页面里。实测北京 9/15 正午太阳高度 53.11°，理论值 53.3°，方位 182.2°（正南）。
不联网、无 API key，所以遮荫模拟离线也能跑。

**2. 遮荫率 = 冠层覆盖 × 0.86 × sin(太阳高度角)**
物理含义：太阳越高，头顶冠层的垂直遮挡越有效；太阳贴地时阳光侧射绕过树冠。
同一棵树，正午 54% 遮荫，太阳 8° 时只剩 13%。太阳低于 8° 时**不显示遮荫率**——
模型在此失效，显示一个接近 0 的数会让人以为系统坏了，改为显示「太阳低斜」。

冠层覆盖值来自两部分加权：
```
canopy = 类型先验 × (1-w)  +  (0.10 + 0.82 × 邻域树密度) × w
```
其中树密度取自 OSM `natural=tree` / `tree_row` 的 330m 网格统计。

⚠️ **关键处理：缺失数据 ≠ 零。** OSM 中国区树木标注极稀疏（4337 个点里仅 1345 个有实测数据）。
若直接把无数据的地方算成 0，90% 的点会塌到 0.15，而北京明明树很多。
所以大范围无树木数据时不判定为「没树」，而是判定为「没人标」，回落到城市均值，
并在详情卡里如实说明依据的是「12 处 OSM 行道树数据」还是「该处无数据，按类型估算」。

**3. 评分由「户外意愿」主导，不是线性加权**
第一版用线性加权，结果完美春天（24°C、UV2）户外最好的地方也只排第 15，博物馆永远霸榜——
等于树荫这个功能白做了。改成由 `outdoorDrive`（现在适合待在户外吗）主导：

| 场景 | Top1 | 最佳户外排名 |
|---|---|---|
| 春天午后 24°C UV2 | 奥林匹克森林公园 | 1 |
| 酷暑正午 35°C UV9 | 中国科学技术馆 | 15 |
| 傍晚 18:40 | 什刹海环湖 | 1 |
| 冬天 3°C | 中国科学技术馆 | 15 |

## 怎么跑

**直接用**：双击 `index.html`。天气会联网拉 Open-Meteo，失败自动降级到本地估算并在界面标注「离线估算」，不假装实时。

**重建数据**（可选，约 27 分钟，需要联网）：

```bash
python3 tools/fetch_osm.py      # 第一轮：POI      -> data/raw1/
python3 tools/fetch_geom.py     # 第二轮：树 + 地铁 -> data/raw2/
python3 tools/process_osm.py    # 清洗             -> data/osm_places.js
python3 tools/inject_data.py    # 注入 index.html
```

两轮输出目录刻意分开（`raw1/` `raw2/`），否则同名 `t*.json` 会互相覆盖。
纯标准库，无 `pip install`。

**已知边界（没做，不粉饰）：**

- **面积字段缺失** —— Overpass 的 `out bb` 在所用镜像上不返回，所以没有「这个公园多大」。
- **通勤时间是直线距离**，不是真实步行路径（地铁距离同理，用的是最近站点的直线距离）。
- **OSM 中国标签极稀疏** —— 6662 个元素里带厕所标签的只有 15 个。设施信息按「未知」处理，不假装知道。
- **运动场地占 65%**（学校操场、篮球场都在 `leisure=pitch` 里），会淹没小公园，故默认收起，侧栏可开关。
- **场馆开放时间、地铁线路为人工整理**，可能有误，UI 内已提示出门前再核一次。
- 没有降雨图层、没有预约余票接口。
